# Заказы и приёмка арта, анимации и звука

Справочник для потоков и менеджера (перенесено из `CLAUDE.md` 21.11.2026, решение владельца). Читать нужный раздел по задаче, целиком не читать.

`main` хранит текущее состояние, задачи — в Issues, работа приходит короткими PR. Долгоживущих веток у художника
и тестера нет. В начале каждой сессии — страница «Где мы» (#645), открытые issues и PR (REST: `gh api "repos/garrimajo5/DeepDive/issues?state=open"`,
`gh api repos/garrimajo5/DeepDive/pulls`; GraphQL из сессии закрыт). Параметры с кириллицей — через `gh api -X GET … -f labels=баг`, не в строке URL
(`?labels=баг` отдаёт HTML).

**Художник (Codex)** — правила для него: `AGENTS.md`, `art/ARTIST.md`.
- Заказ — issue с меткой `art` или `model`: назначение, исходник, размеры, что сдать, бюджет, критерии приёмки.
  Заказ с ракурсами из игры — у каждого кадра полная команда снимка (`shot.gd` с ключами) и сверенные между собой высоты,
  глубины и углы (#1350, 13.11, ART-085). Вид «из кресла» — ещё кадр 1280×720 с наложением органов управления
  `Touch.Layout`: что закрывают крестовина и кнопки (#1350, 14.11, ART-085).
  Держать 3–5 открытых заказов; модели заказываем только по принятому концепту.
- Заказ света (таблицы источников, как ART-064): рядом с позицией каждого омни-огня — линия видимого
  светильника (плафона); омни в ~0,4 м от поверхности без видимого источника гарантированно даёт горячее
  пятно «из ниоткуда» (#1350, поток А, 25.11 — баг #2104).
- Метки состояния: «в работе», «на приёмке» (ставит художник), «правки», «ждёт владельца», `on-hold` (ставим мы).
  `on-hold` — задача **отложена владельцем намеренно**: её и её черновую PR никто не берёт, пока владелец не снимет
  метку; в лимит «3–5 открытых заказов» не считается. Отличие от «ждёт владельца» (нужен ответ, чтобы продолжить):
  по `on-hold` решение уже есть — подождать. Метка общая, не только для арта (владелец может отложить любую задачу).
- Работа приходит PR из ветки `art/<номер>-<кратко>` с `Closes #N`. Приёмка — в той же PR: посмотреть каждый файл
  глазами (модель — ещё и в Godot), лучшие картинки перенести в `docs/concept-art/` под понятными именами с заметкой
  `<имя>.md` (раздел «Решения и привязка к игре»), GLB — в `models/` (его текстуры — `compress/mode=2`, сжатие для
  видеокарты, тест `test_texture_import`), исходник пробы шейдера, на который ссылается заметка, — рядом с ней в
  `docs/concept-art/` (в заметке — его `render_mode`), черновую папку `art/<номер>-…/` удалить; новый тест приёмки —
  после `--import` `git status`: его `.uid` уходит в ту же PR,
  слить PR — issue закроется. Правки — метка «правки» и список в комментарии; художник дописывает в ту же ветку.
- Решения по уже принятым заказам — в `docs/concept-art/*.md` и `docs/concept-art/prinyatye-zakazy.md`.
- Принятые тексты `TXT-…` — в `docs/teksty/TXT-NNN-<кратко>.md` (тексты и раздел «Решения и привязка к игре»), черновую
  папку `art/TXT-…/` удалить.
- **Анимации — тоже Codex**: скелет и клипы на уже принятой модели (Blender, без новой генерации Meshy). Заказ —
  issue `ANIM-NNN: …` с метками `анимация` + метка потока (существа и места — поток Б, экипаж и подвижные части
  корабля — поток А), подзадача нужного эпика; в описании — исходная модель в `models/`, клипы (имя латиницей,
  длина, цикл или разовый, что делает), кости, критерии приёмки. Правила для Codex — `art/ARTIST.md`, «Анимации».
  Заказ от первого лица — сразу эталон стенда: камера, которую игра ставит фактически (глаз и матрица, замер
  headless), фигура в позе у поста и досягаемость — от плеча до цели; дальше руки — сразу «в проекции» (#1350, 12.11, ANIM-003).
  Числовые пределы (размах, скорость, ускорение) — отдельно от описательных фаз: что жёстко (длина, ключевые позы,
  момент удара), а что — ориентир с допустимым окном экстремума (#1350, 13.11, ANIM-005).
  **Приёмка** — как у модели, плюс тест на импорт (образец — `tests/test_eco_serp_anim.gd`: один скелет, skin у
  сеток, все клипы, циклы зациклены и бесшовны, ключевая поза; цикл в `.glb.import` — одна строка
  `"settings/loop_mode": 1` в `_subresources` клипа, блок `slice_*` не нужен — `--import` сам развернёт его в тысячи
  строк `slice_*`, это нормально, в PR не сжимать; шаг ходьбы — по скорости опорной стопы, образец
  `test_crew_anim.test_walk_stride`, #1350, 11.11; клипы на 60 кадров/с — в `.glb.import` явно `animation/fps=60`: по
  умолчанию 30 прореживает ключи и возвращает пики ускорения, #1350, 14.11, ANIM-005); GLB — в `models/`, лист фаз и GIF — в
  `docs/concept-art/`; встраивание в сцену и замер на телефоне — **отдельная задача** (пункт в эпике).
  Заказ с пределами ускорения — в описании сразу настройки импорта (`animation/fps`, оптимизатор `AnimationPlayer`)
  и какие кости разовый клип двигает поверх плавания (фильтр костей при смешивании). Вес смешивания по времени —
  smoothstep или экспонента, не `move_toward`: излом на концах рампы даёт рывок (#1350, 14.11, ANIM-005).
- **Звук, музыка, голоса — тоже Codex, через ElevenLabs** (MCP `elevenlabs-mcp`, аккаунт владельца на тарифе **Creator** с 07.11.2026 — с коммерческой
  лицензией; файлы, сделанные раньше на Free, перечислены в `docs/zvuk.md` и перегенерируются к этапу 7; паспорт, Р6).
  Что нужно игре — звуковая карта **`docs/zvuk.md`** (опись по системам, приоритеты, форматы, шины громкости).
  Заказ формирует поток-владелец звука (корабль, интерфейс, музыка — поток А; существа и места — поток Б): issue
  `SND-NNN: …` с метками `звук` + метка потока, подзадача эпика #641 (голоса — #632), в описании — таблица файлов
  (имя, где звучит, петля или один раз, длина, характер, «что не надо»), на чём проверить, критерии приёмки; в карте —
  номер заказа у строки. «Тише/громче другого звука» — со ссылкой на файл-эталон, абсолютные LUFS — справочно
  (эталон мог смениться). Правила для Codex — `art/ARTIST.md`, «Звук и музыка».
- **Приёмка звука** (ни Kimi, ни Codex звук не слышат): техпроверка — формат, длина, пик, стык петли (`ffprobe`/
  форма волны), выбор варианта по описанию в `notes.md`; файлы — в `audio/<группа>/`, встраивание — по шинам громкости
  из карты, в карте — «готов». Ссылки на варианты — в issue (`tools/issue_img.py` даёт «▶ послушать»), чтобы владелец
  мог послушать с телефона; **музыку (тему меню, напряжение) выбирает гейм-дизайнер** (уровень «по умолчанию»: 48 ч на
  возражение владельца). Тестер
  слушает в игре на устройстве: в PR приёмки звука вместо `Closes #N` — «По issue #N», заказу — метка «проверить»,
  закрывает тестер, послушав.
