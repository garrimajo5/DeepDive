# Тестер: проверка сборок на устройстве

Тестер — владелец и локальный Claude на его компьютере (Windows, эмулятор Android `Pixel_8`, телефон).
Код и правила игры живут в `main`, задачи тестера — в GitHub Issues, отчёты приходят PR в `main`.
Долгоживущих веток у тестера нет.

## Что проверять
1. **Свежая сборка** — APK из релиза `apk-latest` (собирает CI из `main`, коммит — в заметке релиза).
   CI собирает APK только когда меняется код: после слияния PR, где были лишь `art/`, `qa/`, `*.md`, картинки или html
   в `docs/`, тесты и APK пропускаются (в Actions — «skipped»), и коммит в заметке релиза отстаёт от `main`. Игра при этом
   та же. Если нужно проверить самое последнее состояние или сомневаешься, что сборка свежая, — собери APK сам (ниже).
2. **Исправленные ошибки** — открытые issues с меткой «проверить»: в каждом сказано, что исправлено и как проверить.
   Вся очередь тестера одним списком — строка «Тестер» на странице **«Где мы» (issue #645)**: «проверить» и задачи `qa`
   в эпиках (полный забег с хронометражем, проверка вдвоём, слабый телефон, кадры для Google Play).
3. **Что ждёт первой проверки** — PR последних слияний, где написано «ждёт проверки на устройстве».
4. **Фикс из открытой PR** — можно проверить ещё до слияния: `run-qa.ps1 -Pr <номер>` берёт APK из артефакта
   её прогона CI. Подтвердил — фикс сливается уже проверенным, и баг закрывается сразу (см. «Как сообщать»).
5. **Звук** — его делает Codex через ElevenLabs, а Claude и Codex его не слышат: ты единственный, кто слушает в игре.
   Новые звуки (звуковая карта `docs/zvuk.md`, заказы `SND-…`): громкость относительно друг друга, щелчки на стыке
   петель, слышна ли тревога поверх эмбиента, не режет ли ухо. Замечания — issue «баг» с метками `звук` и потока.

## Как проверять
- Клон: `D:\AI\DeepDive` (ветка `main`). Перед прогоном — `git -C D:\AI\DeepDive pull`: скрипты меняются вместе с игрой.
- Прогон: `powershell -ExecutionPolicy Bypass -File D:\AI\DeepDive\tools\qa\run-qa.ps1` — скачивает APK из релиза, ставит на эмулятор
  и запускает **сценарий** `tools/qa/scenario.json`: игра сама проходит шаги (сесть за штурвал, полный ход, поворот,
  встать…) через те же органы управления, что и пальцы, снимает скриншоты и пишет лог состояния — без тапов по координатам.
  Результат — `D:\AI\qa-build\run\` (`*.png`, `log.txt`, `logcat.txt`). `-Force` — прогнать тот же коммит ещё раз.
- Проверить фикс из открытой PR до слияния: `run-qa.ps1 -Pr <номер>` — берёт APK из артефакта `deepdive-apk`
  последнего прогона CI этой PR (нужен `gh`), ставит и гоняет тот же сценарий. `NO_ARTIFACT` — в PR нет кода
  (сборка APK не шла); `NO_RUN` — CI ещё не прошёл.
- `-ExecutionPolicy Bypass` обязателен: в Windows запуск `.ps1` по умолчанию запрещён («выполнение сценариев отключено
  в этой системе»). Ключ разрешает только эту команду, настройки системы не меняются.
- **Собрать APK самому** (Android SDK на компьютере не нужен — собирает CI):
  - из `main`: GitHub → Actions → «Godot» → Run workflow, ветка `main` (или `gh workflow run godot.yml --ref main`).
    Прогон гоняет тесты, собирает APK и обновляет релиз `apk-latest`; минут через 10 запускай `run-qa.ps1` как обычно
    (`-Force`, если коммит в заметке не сменился).
  - из ветки PR, которую ещё не слили: тот же Run workflow с этой веткой. Релиз не трогается, APK — в артефакте
    `deepdive-apk` на странице прогона (`gh run download -n deepdive-apk`); ставить вручную: `adb install -r DeepDive.apk`.
- Быстро без эмулятора: `run-qa.ps1 -Pc` — та же игра из клона в Godot на компьютере (`D:\Godot`). Годится, чтобы
  проверить сценарий и картинку; касания, частоту кадров и вылеты на Android — только на эмуляторе или телефоне.
- Частота кадров в логе: у каждого скриншота — средние «кадр/с» и **худший кадр** (мс) с прошлого скриншота: разовый
  провал (сборка шейдера) виден по худшему кадру, а не по среднему. Оба считаются без кадра самого скриншота
  (снимок на телефоне стоит сотни миллисекунд, issue #169). В скобках у худшего кадра — шаг сценария, на котором он
  был (номер с единицы, как в `scenario.json`), сколько из него занял код игры, отрисовка и, если драйвер
  умеет замерять, на видеокарте: «худший кадр 726 мс (шаг 54 press, код 5 мс, отрисовка 700 мс, видеокарта 690 мс)».
  Отрисовка — того же кадра, от начала до конца отрисовки, вместе с ожиданием видеокарты и показа кадра (issue #609:
  раньше замер движка запаздывал и приходил от чужого кадра). Видеокарту движок замеряет с запаздыванием — если она
  больше самого кадра, её нет в строке. Велика отрисовка — сборка шейдера, выгрузка или ждали видеокарту; велик код —
  тормозит игра (код от 20 мс — с частями шага, issue #627: «код 112 мс (мир 80, виды 20; шаг 120 мс)» — мир —
  живой мир и его существа, корабль — системы и посты, виды — узлы корабля и экипажа, интерфейс — панели и подсказки;
  «шаг» — если время кадра больше 50 мс, живой мир считает его по частям); оба малы — время ушло вне шага и отрисовки (физика, ввод, система) (issue #217, #281). Средние кадр/с — по своим кадрам, без трёх кадров сразу после
  скриншота (на эмуляторе они долгие из-за самого снимка, issue #435); если строка описания пришла раньше — вместо числа
  «— кадр/с», это не просадка. Эти скобки переносить в отчёт вместе с числом. Первая строка после заголовка — «прогрев шейдеров:
  N кадров, M мс» (при запуске игра под шторкой «Погружение…» оглядывает корабль, сценарий ждёт, issue #50), за ней —
  «прогрев по кадрам»: «до первого кадра» (сборка сцены, не кадр), затем ровно N длительностей кадров и номер худшего
  с единицы.
- Свой сценарий: `-Scenario <файл>`; шаги описаны в начале `scripts/core/qa_script.gd` (wait, shot, press, hold, swipe, goto, hot, log).
- **Кадры для Google Play** (ART-046): `run-qa.ps1 -Scenario D:\AI\DeepDive\tools\qa\play-kadry.json` — игра прячет
  кнопки (шаг `hud`) и снимает четыре кадра (шаг `play`): в результате `kadr-1.png … kadr-4.png` — готовые 1920×1080 с
  подписью сверху и снимком в рамке 16:9 с тёмными полями, рядом `kadr-N-snimok.png` — снимок как есть. Снимать на
  **телефоне** (тени и SSAO только там; эмулятор — проверить ракурсы). Не тот ракурс или за окном пусто — поправить
  `goto` в сценарии или снять экран телефона самому и собрать кадр: `godot --path . -s tools/play_frame.gd -- снимок.png
  kadr-3.png 3` (в облаке — под `xvfb-run` с `--rendering-method gl_compatibility`). Кадры — в отчёт; публикация — решение владельца.
- На телефоне — ставить по ссылке из `README.md` и смотреть то, чего эмулятор не покажет: удобство управления,
  читаемость подписей, плавность.
- **Полный забег с хронометражем** (эпик #633) — играть руками на телефоне от «Погрузиться» до итога (или до «Корпус
  разрушен»); игра сама пишет хронометраж каждого забега — когда началось и кончилось каждое событие (пробоина, сонарная
  тьма, присоска, перегрев, сброс реактора, голосование), удары по корпусу, точки маршрута, разряды, — и сводку: длина,
  доля под событиями, **самое долгое затишье** (где скучно) и сколько шли **два события сразу** (перегруз). Забрать:
  `powershell -ExecutionPolicy Bypass -File D:\AI\DeepDive\tools\qa\zabeg.ps1` (телефон по USB с отладкой или эмулятор;
  `-Clear` — стереть после). В отчёт — файл целиком и свои впечатления по отрезкам ленты («00:40–03:20 — скучно»).
  Свернули игру посреди забега — он записан «не закончен» и дописывается, если вернуться. Прогон сценария пишет свой
  хронометраж в `zabeg.txt` рядом с логом (файл игрока не трогает).
- Сохранение сценарий не проверяет (прогон всегда с пустого трюма и ничего не записывает) — руками: поднять образец
  лебёдкой, закрыть игру из списка приложений, открыть снова — образец в трюме, на дне его нет.

## Как сообщать
- **Новая ошибка** — issue с меткой «баг»: что делал, что ожидал, что получил, коммит из заметки релиза,
  устройство, ссылка на папку отчёта. Одна ошибка — один issue.
  **Снимок — прямо в issue, а не только его имя** (`08-power` владелец открыть не может): если ошибка видна в кадре —
  `python3 tools/issue_img.py <N> qa\out\08-power.png "что не так"` (ветка `issue-img`), без Python — перетащить
  картинку мышкой в комментарий issue в браузере.
- **Исправление подтверждено** — лучше всего в самом issue комментарий «Проверено на <коммит>, <устройство>» и
  **сразу закрыть** issue: `gh issue close <N> -c "…"`, без `gh` — в веб-интерфейсе. Если закрыть забыл — не страшно:
  строку «Проверено на…» в разделе «Issues проверить» отчёта поток А увидит при слиянии и закроет issue за тебя.
  Не исправлено — комментарий в issue, что видно сейчас, и снять метку «проверить» (чтобы его не закрыли по ошибке).
- **Отчёт прогона** — папка `qa/<ГГГГ-ММ-ДД-ЧЧММ>-<что проверял>/` с `report.md` (коммит, устройство, что работает,
  ошибки со ссылками на issues, лог-выжимка) и 2–4 скриншотами JPEG до 300 КБ. Сдать:
  `powershell -ExecutionPolicy Bypass -File tools\qa\publish-qa.ps1 -Folder <папка> -Message "<сообщение>"` — ветка `qa/<папка>` от свежего `main`, пуш и PR.
  Без `gh` скрипт только пушит ветку — PR откроет Claude.
- Claude читает отчёт, **закрывает каждый issue, помеченный «Проверено на…»**, заводит недостающие issues и сливает PR.
  Слитая PR — отчёт учтён, подтверждённые баги закрыты.

## Метки
- «баг» — ошибка, найденная на устройстве.
- «проверить» — Claude исправил, нужна проверка на устройстве (ставит Claude в PR исправления).
- `qa` — роль тестера в эпиках: задача для тебя (не ошибка), например полный забег на телефоне с хронометражем.
