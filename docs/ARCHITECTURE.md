# Архитектура «Погружения»

Godot 4.7.2, GDScript, Android (альбомная, рендерер Compatibility). Один разработчик-ИИ на поток, два потока (A и Б),
художник Codex, тестер на компьютере владельца. Правила работы — `CLAUDE.md`, план — `ROADMAP.md`.

## Главные решения
1. **Логика отдельно от сцены.** `scripts/core/` — чистые расчёты без узлов (static-функции и `RefCounted`): ход
   корабля, реактор, рельеф, экосистема. Их проверяют быстрые тесты без рендера. `scripts/game/` — узлы: рисуют то,
   что посчитала логика, и переводят ввод в команды. Узел не хранит игровое состояние, которого нет в `core`.
2. **Сцена из кода.** `scenes/main.tscn` — только корень с `main.gd`; всё строится в `_ready()`. Нет ручных сцен,
   которые надо открывать в редакторе, — меньше конфликтов и всё видно в диффе.
3. **Мир неподвижен, движется корабль.** Узел «Корабль» ставится по `Helm.Ship` каждый шаг; камера — глаза игрока
   в осях корабля. Отмель и существа живут в мире.
4. **Детерминизм.** Один шаг игры — `Main.step(dt)`; случайность только из своего генератора по зерну (mulberry32,
   как в браузерном прототипе). Повтор с тем же зерном и вводом даёт тот же мир — на этом тесты, сценарий тестера,
   а позже сеть (хост считает мир, клиенты получают снимки).
5. **Модели художника — как есть.** GLB из Meshy грузятся напрямую; места и масштабы — константы в `core`
   (`BridgeProps`), свечение — в GLB или шейдером огней (`TextureGlow`).
6. **Бюджет телефона.** < 260 вызовов отрисовки, < 350 тыс. треугольников. Однотипное — одним мешем или MultiMesh
   (стаи, мох, образцы), детали отсека — один меш по краскам. Сейчас 26–56 вызовов.

## Оси и единицы
Метры, секунды. Y вверх, лёд на y = 0, дно ниже. Нос корабля −Z (на картах — север), правый борт +X (восток).
Отсеки в осях корабля: пол y = 0, мостик z −6…2, коридор 2…8, лаборатория 8…14, машинное 14…19,5, трюм 19,5…24.
`rotation.y` растёт — поворот влево; курс yaw = 0 — нос на север. Числа из браузерного прототипа (`js/…`) переносим
без смены знака; в Unity-коде (`Core/…cs` в pogrujenie) x стоит со знаком минус.

## Дерево сцены
```
Main (main.gd)                    — шаг игры, пилот, посты, сообщения, связь подсистем
├─ WorldEnvironment               — вода по глубине (OceanView.apply_water)
├─ Отмель (OceanView)             — дно, лёд, морской снег, свет сквозь лёд          [слой 1]
├─ Живой мир (EcoView)            — существа и флора (поток Б)                        [слой 1]
├─ Корабль (Node3D по Helm.Ship)
│  ├─ Мостик (BridgeView)          — оболочка, модели, ползунки, люк                   [слой 2]
│  ├─ Отсеки (RoomsView)           — коридор…трюм, люки, реактор                       [слой 2]
│  ├─ Экипаж (CrewView)            — фигуры экипажа, модели MOD-012 по CrewRig          [слой 2]
│  ├─ Прожектор (SearchlightView)  — свет на отмель и конус луча                       [слой 1]
│  ├─ Корпус (HullView)            — корпус снаружи по HullPlan, роторы и рули          [слой 1]
│  └─ Глаза (Camera3D)
└─ Интерфейс (CanvasLayer)        — приборы, пульт энергии, экранное управление
```
Слой 1 — то, что за бортом: его освещают лёд и прожектор. Слой 2 — корабль изнутри: только свои лампы.

## Шаг игры (`Main.step(dt)`)
1. Сценарий тестера (если есть) нажимает «пальцы».
2. Ввод → игрок: за штурвалом — тяга, поворот, всплытие, свет; у пульта — доли энергии; иначе — ходьба и посты.
3. Люки, реактор (`k` систем), ход корабля (`Helm.Ship` с силой двигателей и течением), прожектор.
4. **Живой мир:** корабль заполняет `EcoLink.ShipState`, `EcoView.step` возвращает события, `Main.on_eco_event`
   решает, что они значат для корабля.
5. Расстановка узлов: корабль, камера, ползунки, люки, реактор; строка состояния.

## Живой мир (поток Б)
Перенос экосистемы из браузерного прототипа (`js/creatures.js`, 26 видов отмели) и Unity-версии (`Core/Eco*.cs`).
- `core/eco/eco_world.gd` — мир без узлов: генератор по зерну 20261018 (`EcoRandom`, mulberry32 число в число),
  шина событий между видами (`E.emit`), существа (`EcoAgent`: место, скорость, состояние «пасётся / идёт / охотится /
  убегает / прячется»), модули видов (`reset(world)`, `step(world, dt)`), подшаги ≤ 0,05 с.
- Модуль вида — файл `core/eco/<вид>.gd`: правила поведения и связи (хищник берёт рыбу у модуля стай и т. п.).
  Его вид — `core/eco/<вид>_look.gd` (из чего собрать меш, цвета) и узел в `game/eco/`.
- Реестр видов `core/eco/species.gd`: имя, падежи, описание и заметки журнала (из `docs/bestiary.md`).
- Мир знает о корабле только `EcoLink.ShipState` и говорит с ним только событиями `EcoLink` (удар, тянет энергию,
  рядом заметное существо, сообщение). В шаг с `sonar_ping` мир шлёт `NEAR` (с `pos`) для каждого заметного существа
  ближе `sonar_range` — это отметки на голограмме сонара. Сонар, разряд, урон корпусу, тревоги — поток А, по этим событиям.
- Существа не проходят сквозь корпус: `HullPlan.inside_world(точка, ShipState.pos, ShipState.yaw)` (`core/hull_plan.gd`,
  поток А) — точка внутри корпуса корабля, стоящего в мире.

## Сохранение и сеть (позже)
Состояние игры — данные в `core` (доли реактора, груз, просканированные виды, мир по зерну + изменения).
Сохранение — снимок этих данных в `user://save.json` (`core/save_game.gd`, формат как `js/save.js`; груз,
поднятые образцы и изученные виды). Для коопа хост считает `Main.step`,
клиентам уходят снимки; поэтому в `core` нет ссылок на узлы и всё сериализуется. Фигура игрока — `Crew.Member`
(место, курс, поза, фаза шага; `snapshot()`/`apply()`); свой игрок рисуется без головы (камера в ней), стоя — ещё
без груди и плеч, другие — целиком с цветом роли.

## Тесты
`tests/test_*.gd`, свой раннер `tests/run.gd`. Логика — быстрые тесты без сцены; сцена — через `Main.step(dt)` с ровным
шагом. Каждая фича и исправление — с тестом. Тесты одного потока не зависят от файлов другого, кроме `EcoLink`.
