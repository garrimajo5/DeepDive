## Масштаб и сила
Пол: шаг ячеек100мм поперёк и62,5мм вдоль; соседние ряды сдвинуты на50мм. Щель около64×16мм, края скруглены; глубина исходного профиля3,5мм. Это **перфорированная решётка на закрытом поддоне**, не настоящие сквозные отверстия: материал непрозрачный, без альфа-вырезания, не видно океана сквозь пол. Ничего не меняется в коллизиях. При необходимости настоящего просвета/параллакса понадобится отдельный заказ на геометрию.
Стена: панель1×0,5м, канавка до0,9мм, головки около16мм в диаметре и1,2мм высотой. Малые трафареты4–5см: скобка и пустой ромб, без букв, стрелок и нового сюжетного значения.
Потолок: крышка короба шириной23см, визуальный рельеф до2,4мм; три тонкие кабельные дорожки и вентиляционный участок25×60см. Это неглубокая иллюзия поверхности, не выступающие в проход короба. Рельеф/декор не отбрасывают настоящие геометрические тени.
Стартовые normal_map_depth: **пол0,6; стена0,8; потолок0,7** (так на листе). При мерцании пола вдали снижать его силу, а не увеличивать резкость. Включать корректные mipmaps/анизотропную фильтрацию для взгляда вдоль пола. Эмиссия всех девяти карт0.

## Каналы и импорт
Цвет — sRGB; normal/ORM — линейные данные, не source_color.
Нормали **OpenGL+Y**, не переворачиватьG. Тест выпуклого купола: верхний склонG>128, нижнийG<128. Плоская нормаль(128,128,255). Нормали получать в касательном базисе после корректных метровых UV.
ORM: **R=AO (1открыто,0затенено), G=roughness, B=metallic**. Это не specular/gloss, roughness не инвертировать.
Ориентиры фактических диапазонов:
- Пол: AO0,68…1; roughness0,51…0,73; metallic0,35…0,72.
- Стены: AO0,87…1; roughness0,62…0,85; metallic0,02…0,51 (трафареты неметаллические).
- Потолок: AO0,78…1; roughness0,67…0,83; metallic0,12…0,34.
Точные диапазоны/хеши в validation.json. AO — только контактное затемнение ячеек и швов, направленного освещения в картах нет. ПодключатьR в AO соответствующего PBR-материала, не умножать всю сцену на него повторно.
Все карты Repeat, linear+mipmap. Для телефона normal map сжать как normal, ORM без sRGB с сохранением отдельных каналов; проверить ASTC/ETC2 на ступенчатость. Насыщенные цвета ORM/normal — данные, не цвет стен.

## Подключение без новых вызовов
Новых мешей/GLB/декалей не сдано. Три комплекта предназначены для существующих поверхностей оболочки:
- Paint.DECK — пол.
- Paint.METAL — большие стеновые панели.
- Paint.SEAM — потолок; сохранять отдельное назначение тёмных подложек ламп.
Скос потолка сейчас Paint.METAL: различить его и стены внутри того же материала по признаку грани/вершины либо локальной нормали/высоте. Не разбивать общую поверхность на новые draw surfaces только ради карт; сохранять нынешнее объединение по Paint. Для участков потолка/стены в общем материале выбирать соответствующий комплект, а не накладывать второй проход. Подложки плафонов, рамы и рёбра можно оставить исходной заливкой через маску/признак; не накрывать вентиляцией светящиеся приборы.
**Сейчас BridgeView._add_box ставит всем вершинам UV(0,5,0,5)**. Простое присваивание текстуры не сработает: Claude должен назначить метровые планарные UV без растяжения и заново получить касательные либо использовать согласованную локальную проекцию с правильным базисом нормалей. Период не подгонять под размер грани:1UV=1м. На потолке кабельные короба идут вдоль корабля. На стены рисунок ставить вертикально, не зеркалить нормали на противоположном борту.
Эта сдача содержит только художественные материалы; код/разбиение поверхностей игры не менялись. Сохранение числа draw calls — условие интеграции, в Blender-иллюстрации оно не измерялось.

## Свет и проверка
Лист использует **настоящие размеры BridgePlan** текущей игры (10×7,9×3,2м), не старую перспективу6×8×3м ART-002. Пульт энергии, ползунки и задний люк импортированы из принятых models/ без переработки. Размеры/положение взяты из BridgeProps. Модели приведены только как ориентир читаемости рядом с новыми текстурами.
Это Blender/Cycles-примерка, **не игровой кадр Forward Mobile**. В каждой паре одинаковы камера/источники света; меняются только материалы оболочки. Тёплый режим: свет#F6DEAC сверху; голубой: доминирует#67DDEB возле пульта при слабом тёплом заполнении. Значения мощности Blender не являются готовыми Godot light_energy. Для наглядного AO сравнения в Blender использовано четвертное затемнение диффузного цвета; это приближение, при интеграции подключать стандартный AO отдельно.
Все карты и оба листа просмотрены. Противоположные края каждой из девяти карт совпадают побайтно, режимRGB8, размер1024², лимит2МБ проверен. Повтор3×3 не создаёт дополнительной пустой рамки/плиточной засветки; закономерные швы панелей и рисунок решётки повторяются как конструкция. Один трафарет/вентиляционный модуль действительно повторяются каждый метр — ограничение единственной плитки, не уникальные таблички.
При встройке проверить реальные плафоны, движение камеры вдоль пола/moire, сжатие телефона, UVна всех сторонах, сохранение контраста экипажа и счётчика вызовов. Эти проверки на устройстве здесь не проводились.

## «Экономно» и палитра
На «Экономно» выключать normal-выборки; при необходимости ORM заменить постоянными: пол roughness0,72/metallic0,4, стена0,8/0,15, потолок0,78/0,2, AO1. Цвет оставить. Отключать карты веткой/вариантом материала, а не ставить силу0 с сохранением всех выборок. Мелкие щели остаются читаемыми по цвету; геометрия/игровые возможности не меняются.
Палитра: #34484C настил,#1C2728 дно ячеек,#8C806B стеновой металл,#514D43 швы,#6E6859 потолок,#BEBBA1 слабый трафарет,#67DDEB только приборы/их свет,#F6DEAC плафоны. Красных красок/сигналов нет.
Самостоятельно предложены продолговатая решётка с поддоном, размеры панелей/крепежа, два абстрактных трафарета и рисунок кабельных дорожек. Все элементы в существующей семье ART-002/ART-008/ART-024. Вопросов владельцу нет.
